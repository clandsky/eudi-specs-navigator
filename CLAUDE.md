# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**specs-navigator** is a static web app, an API explorer for EUDI Wallet issuers (OpenID4VCI) and verifiers
(OpenID4VP). For every flow, step, message and field it shows which spec defines it, which specs override it, and the
effective rule as of a date. Planning inputs: `03-initial-prompt.md` (the brief), `context/01-spec-catalog.md` (every
spec, pinned versions, precedence, known traps), `context/02-eudiw-project-summary.md` (sister project). Read the
catalog before adding any assertion.

State: all five v1 flows exist. Issuance with authorization code + PAR is fully sourced; the pre-authorized code flow
and the three presentation flows (redirect same device, redirect cross device, Digital Credentials API) are sketched:
every entry is clickable, most are sourced, the rest are listed under "Not sourced yet" on the review page. The project
owner resolves spec discrepancies over time through go-live overrides and edited example bodies, so record conflicts
(`needs-review`) but don't stop to chase them.

## Commands

```bash
pnpm dev                      # Vite dev server; also enables writing go-live compromises from the UI
pnpm test                     # Vitest: resolver worked examples, JWT signatures, JSON pointers, quote matching
pnpm vitest run src/model/resolve.test.ts -t "worked example B"   # one test
pnpm validate                 # Zod schema + cross-reference check of everything under data/
pnpm sources:build            # pdftotext/copy/download the pinned sources into sources/*.txt (git-ignored)
pnpm quote-check              # find every assertion quote in its source text; writes verified: back into the YAML
pnpm quote-check --ci         # read-only; fails if a source-checked or needs-review quote is not found
pnpm examples:build           # sign examples with test keys (only changed ones; --force re-signs all)
pnpm c2bo:import              # snapshot https://conformance.c2bo.net/api/requirements and report coverage (--offline: report only)
pnpm build                    # validate + typecheck + vite build + dist/issuer.openapi.yaml
pnpm typecheck
```

After editing data: `pnpm validate && pnpm quote-check && pnpm test`. After editing an example's http/json/jwts:
`pnpm examples:build` (tests fail on a stale encoded file).

## Precedence (project owner's default)

**Assumptions > temporal go-live compromises ("d-you") > CIR implementing acts > ETSI > HAIP > base
protocols > primitives > ARF**, encoded in `data/layers.yaml` (lower rank wins). The German implementation layer (`impl-de`) never decides, it is shown as
implementation with deviations flagged. `secondary` sources (c2bo conformance tester, Developer Guide) only
cross-reference. Go-live compromises are not in the corpus: the project owner adds them through the in-app editor;
never invent one.

## Architecture

- `src/model/schema.ts`: Zod model for layers, specs, subjects, flows, assertions, examples, the c2bo snapshot.
  Assertions split `relation` (defines, profiles, extends, adapts, replaces, voids, implements, deviates, silent) from
  `level` (shall … info); the brief's `requires/recommends/permits/forbids` are accepted as shorthand.
- `src/model/resolve.ts`: the pure precedence resolver. Filter by role/variant, date window and lens; neutralise
  targets of voids/replaces/adapts if outranked (else conflict); highest-ranked remaining level decides; within one
  rank, narrowing statements beat defining ones. A void can let a lower layer surface again (OpenID4VP response
  encryption: CIR voids ETSI, HAIP still requires it). `timeline()` gives rule changes over time.
- `data/`: all knowledge, one YAML list per file. `subjects/` (stable dotted ids = deep-link paths), `flows/`,
  `assertions/<spec>/` (one directory per source), `examples/` (+ generated `*.encoded.json`), `specs/`,
  `test-keys/` (TEST ONLY PKI, generated by `examples:build`), `secondary/c2bo/`.
- `scripts/lib/data.ts` loads and cross-checks the dataset; `vite-plugin-dataset.ts` serves it as `virtual:dataset`
  (the static build has no runtime fetches); `vite-plugin-editor.ts` is the dev-only write-back for the in-app
  editors: go-live compromises to `data/assertions/golive/`, new assumptions appended to
  `data/assertions/assumptions/assumptions.yaml`, edited example bodies back into `data/examples/` (re-signed). A body edit
  saved as an assumption records the changed view pointers under the example's `assumptions` (`src/model/inputs-diff.ts`);
  the object view marks those fields while the Assumptions layer is on. The static build keeps editor drafts in localStorage instead.
- Examples: authors write decoded inputs with placeholders (`{{jwt:name}}`, `{{sdjwt:name}}` with optional `kb` for a
  Key Binding JWT, `{{jwe:name}}` for ECDH-ES encrypted entries, `{{jwk:key}}` / `{{jwk:key#kid}}`, `{{x5c:key}}`,
  `{{x509hash:key}}` and `{{s256:text}}` (both also inline in longer strings), `{ use: example/jwt }` to reuse a JWT);
  `scripts/lib/examples.ts` signs and encrypts, `scripts/lib/build-examples.ts` orders and rebuilds. The UI only shows
  `viewOf(encoded)`.
- Field mapping: every key in every example must resolve to a subject (test-enforced). Resolution order in
  `annotationFor` (`src/model/pointer.ts`): exact example annotation, example pattern, global pattern from
  `data/fieldmap.yaml` (`*` one token, `**` any depth; more literal tokens win). Generic JOSE/JWT/JWK/HTTP/status-list
  fields live in `data/subjects/common.yaml`; JWT names (`wia`, `ka`, `pop`, `dpop`, `proof`, `ro`, `resp`, `pid`,
  `pid-kb`) are mapped globally, so reuse those names in new examples.
- UI: `src/lib/router.ts` (hash routes; `role`, `asOf`, `lens`, `de` are sticky query params so links reproduce a view),
  `src/lib/store.ts` (indexes, view context, lens stages), `src/diagram/SequenceDiagram.tsx` (own SVG renderer;
  Mermaid cannot click messages), `src/components/{ObjectView,StackPanel,OverruleEditor}.tsx`, `src/views/`.
- Layer lens: Base → + HAIP → + ETSI → + CIR → + d-you (the go-live layer) → + Assumptions. The German
  implementation layer switches on from the d-you stage; there is no separate toggle.
- Domain model: the `golive` layer is the wallet solution layer. It holds one solution today, d-you (the name on the
  lens button); further national solutions will follow. "Compare wallets" and "RSS" in the top bar are empty
  placeholders for comparing solutions and for change notifications.
- Assumptions (`data/assertions/assumptions/`, spec `assumptions`, layer `assumption`, rank -1) record how the project
  owner reads a defective or unclear rule: `relation: adapts`, `interpretation: true`, `target` = the literal rule. The
  "Resolve" button (dev server, `/__assumptions/resolve`) moves one into `data/assertions/resolved/<layer>.yaml` with
  spec `resolved-<layer>`; an interpretation may neutralise a target of the same rank. Specs with `authored: true`
  (assumptions, resolved-*, golive-compromises) are skipped by quote-check. The target keeps its `needs-review` flag.
- `src/model/openapi.ts`: OpenAPI 3.1 export, shared by the download button and `scripts/openapi-build.ts`.
- Visual design: calm, document-like look (`src/styles.css` tokens), dark by default with light opt-in. No violet or
  purple anywhere. A busier blueprint style was tried and reverted.

## Rules for adding knowledge

- **Accuracy is the product.** Every assertion quotes the pinned version verbatim; `quote-check` must find it (quotes
  may elide with `…`). Locators carry the requirement ID where one exists; quote-check also checks the ID is near the
  quote. Never hand-set `verified: source-checked`; let quote-check write it. Use `needs-review` with `review.reason`
  for real conflicts or defects in a source, and `silent` with a `probe` term to record that a binding spec says nothing.
- Cite the version the citing spec pins (ETSI 472-3 pins attestation-based-client-auth **-07**, which is in the corpus).
- c2bo quotes are candidates only: re-check them against our own texts before adopting.
- Questions to the user in German; code, data and UI text in English.

## Corpus (`eIDAS + all references/`)

About 300 files; start with its `README.md`. `cir/CIR-2026-1731-…` is the top source; `attestations.md` is a text
extract of its Annex Ib; `standards/` holds ETSI, OpenID, RFC and draft texts. PDFs are git-ignored (size; ETSI texts
must not be redistributed), as are `sources/*.txt`. RFC 7636 and RFC 9126 are not in the corpus; `sources:build`
downloads them. The corpus README refers to `REFERENCES.md`, `REFERENCES-L2.md`, `ETSI-normative-refs.md` and
`REVIEW-2026-amending-CIRs.md`, which are not in this repository. ARF, TS3 and the German wallet docs are not in the
corpus either (pin a release tag when adding them).
